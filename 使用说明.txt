-----------------------------------------------------------------------
 一、修的是什么问题
-----------------------------------------------------------------------

症状：游戏运行中把手柄拔掉再插回去，手柄就再也不响应了，
      必须重启游戏才行（用键鼠还能玩，但手柄彻底失效）。

原因（已用日志实测确认，共两层）：

 1) GER.exe 是 32 位程序，手柄输入走 DirectInput8
    （程序内部有 QDirectInputPad / io::Controller 等符号，
     XInput 只用来做震动：XInputSetState / XInputGetCapabilities）。

 2) DirectInput 的 IDirectInputDevice8 设备对象绑定在"物理设备实例"上。
    USB 手柄一拔，这个对象就永久失效，之后 Poll / GetDeviceState
    永远返回 DIERR_INPUTLOST / DIERR_UNPLUGGED / DIERR_NOTACQUIRED，
    重新插上也不会复活（必须重新 CreateDevice 一个新的对象）。

 3) 更致命的一层：游戏会周期性调用 IDirectInput8::GetDeviceStatus。
    拔掉手柄后它拿到失败结果，就把这个手柄从"活动手柄列表"里删掉，
    再也不去轮询它 —— 所以只能重启游戏。

本修复包做的是一个 DirectInput8 代理层（dinput8.dll），
不改动游戏本体、不改动任何游戏数据/存档：

 - 接管 IDirectInput8 / IDirectInputDevice8（ANSI + Unicode 两种接口）
 - 读取出错时自动恢复：先重新 Acquire；不行就重新枚举 + CreateDevice，
   并把原来的「数据格式 / 属性 DIPROP_* / SetCooperativeLevel /
   事件通知 / Acquire」全部原样重新应用一遍
 - 手柄不在的这段时间上报"中性输入"（摇杆居中、按键全松开），
   游戏看不到"手柄掉了"，也就不会把手柄丢掉（可防止角色乱走、乱按）
 - GetDeviceStatus 对已知手柄返回"已连接"，引擎不会停止轮询
 - 后台看门狗线程：即使游戏某一刻停止轮询，也会继续尝试修复设备
 - 拦截 WM_DEVICECHANGE / RegisterDeviceNotification，
   避免引擎在拔出手柄的瞬间就把手柄从列表里删除

效果：拔掉手柄 → 游戏内只是"暂时没输入"；重新插上 → 自动恢复，无需重启。


-----------------------------------------------------------------------
 二、安装方法
-----------------------------------------------------------------------

  1. 解压整个压缩包（不要只把 dinput8.dll 拖进游戏目录）
  2. 双击「安装.bat」
     - 脚本会自动在 Steam 库中查找游戏目录；
       找不到时会让你手动输入游戏目录路径（含 GER.exe 的那个文件夹）
     - 如果检测到汉化补丁的 dinput8.dll（GECV 加载器），
       会自动改名为 GECV_LOADER.dll 保留，汉化不受影响
     - 如果目录里有别的 dinput8.dll，会自动备份为
       dinput8.dll.backup-时间戳
  3. 安装完成后，照常从 Steam 启动游戏即可

  安装完成后游戏目录里会多出：
     dinput8.dll        修复代理（本补丁主体）
     dinput8_fix.ini    配置
     GECV_LOADER.dll    汉化加载器（仅汉化版会有，勿删）
     dinput8_fix.log    运行日志（可随时删除，仅用于排错）
     dinput8_crash.log  只有在出现异常时才会生成

  不需要安装任何运行库，不需要常驻后台程序，不修改存档。


-----------------------------------------------------------------------
 三、使用注意（重要）
-----------------------------------------------------------------------

  * 请"先插好手柄，再启动游戏"。
    游戏引擎只在启动时枚举一次手柄；启动时没有手柄，之后插上它不会认。

  * 进入游戏后，手柄可以随便拔插，会自动恢复。

  * 如果你"热插拔"后仍然失效：
    先看游戏目录里的 dinput8_fix.log 最后几十行（应能看到
    "pad lost -> keep-alive"、"REPAIRED" 之类的记录），
    把日志附上反馈，方便继续定位。

  * 汉化补丁更新时：请重新运行一次「安装.bat」。
    （汉化补丁会把 dinput8.dll 换回它自己的加载器，需重新安装本修复）


-----------------------------------------------------------------------
 四、可选：无边框全屏（方便来回切窗口）
-----------------------------------------------------------------------

  默认关闭（Enabled=0），需要的话：

   1. 打开 dinput8_fix.ini，把 [Borderless] 里的 Enabled 改成 1
   2. 把游戏设成"窗口化"模式
      （游戏内设置，或改
       %LOCALAPPDATA%\BANDAI NAMCO GAMES\GOD EATER RESURRECTION\config.ini
       里 [GFX] 的 Fullscreen=0）
   3. 建议把游戏分辨率设成显示器的原生分辨率
   4. 游戏内按 F11 可以随时开关"强制无边框"

  说明：无边框模式建议把游戏内垂直同步打开，否则可能有画面撕裂。


-----------------------------------------------------------------------
 五、卸载 / 还原
-----------------------------------------------------------------------

  双击「卸载.bat」即可：
    - 删除 dinput8.dll（仅在确认是本修复时才删）
    - 删除 dinput8_fix.ini / dinput8_fix.log / dinput8_crash.log
    - 把 GECV_LOADER.dll 改回 dinput8.dll（恢复汉化补丁原状）

  手动还原同理：删掉 dinput8.dll 与 dinput8_fix.ini，
  再把 GECV_LOADER.dll 改名回 dinput8.dll。

 六、常见问题
-----------------------------------------------------------------------

  Q: 杀毒软件/Windows Defender 报毒？
  A: DLL 代理（dinput8.dll）这类"劫持"型文件容易被启发式误报。
     本包附带了完整源码（源码 文件夹），可以自行用 Visual Studio
     编译核对；也可以在杀软里把游戏目录加入信任。
     DLL 只依赖 kernel32.dll，不联网、不写注册表、不改游戏文件。

  Q: 会不会影响多人联机 / 被当成外挂？
  A: 它只修复手柄输入设备的读取，不修改游戏内存数据、不修改存档、
     不影响网络同步，不提供任何游戏内优势。

  Q: 支持 Steam Input / DS4Windows / 第三方手柄吗？
  A: 支持。本修复工作在 DirectInput 层，对这些虚拟手柄方案同样有效。

  Q: 支持无线手柄接收器拔插吗？
  A: 支持，原理相同（接收器断开/重连等同手柄拔插）。

  Q: 手柄第一次能识别，热插拔后日志里一直是 "device not present"？
  A: 说明系统层面手柄还没回来（驱动/接收器重连较慢）。
     等几秒会自动恢复；如长时间不恢复，重新插拔一次手柄或检查设备管理器。

  Q: 我想自己编译
  A: 用 Visual Studio（C++ 桌面开发 + Windows SDK）打开「源码」文件夹，
     执行 build.bat 即可生成 32 位 dinput8.dll。
